Terminal commands, by intake sheet column

Run these in Terminal.app (/Applications/Utilities/Terminal.app), or in Recovery via Utilities → Terminal. Output examples are from a MacBook Pro 14" (M3 Pro, Mac15,6) unless noted.
Groups below are named after the intake sheet columns — Name, Serial, Identifier, Model, Battery, Year, RAM, HD, CPU, Physical Issues, Functional Issues, Firmware Locked, OS Reset — so ⌘F for a column name lands on the command that fills it. The step-by-step procedure lives in the Assessment workflow.

Identifier · Name · Model · Year

Four columns off one value. Get the Identifier, then read Name, Model, and Year out of the Models tab.
sysctl -n hw.model
Identifier. Works on every Mac in every state, including Recovery. Record it exactly as surfaced, then paste it into the Identifier filter on the Models tab.
Mac15,6
ioreg -l | grep -i '"product-name"'
Name — the family. Needed on Apple Silicon, where the Identifier (Mac15,6) names nothing; Intel Identifiers (MacBookPro15,2) already tell you. Works in Recovery, where system_profiler often doesn't.
"product-name" = <"MacBook Pro (14-inch, Nov 2023)">
system_profiler SPHardwareDataType
One-shot dump when booted: model name, identifier, chip, cores, memory, serial, hardware UUID, and Activation Lock status. The single most useful command on this page — but unreliable in Recovery.

Serial

ioreg -l | grep -i IOPlatformSerialNumber
Works in Recovery and booted. Also printed on the chassis bottom, and included in the system_profiler SPHardwareDataType output above — you only need one of the two.
"IOPlatformSerialNumber" = "RW2D0HDQRJ"

CPU

sysctl -n machdep.cpu.brand_string
On Intel, record the processor number — the token after Core(TM), e.g. i5-8210Y. On Apple Silicon there is no SKU to parse: record the chip name as-is. If it returns nothing (some recoveryOS builds), derive the chip from the Identifier.
Intel: Intel(R) Core(TM) i7-9750H CPU @ 2.60GHz  ·  Apple: Apple M3 Pro
uname -m
Architecture, and the fastest way to settle which column of the era table applies: arm64 = Apple Silicon, x86_64 = Intel.
sysctl -n hw.ncpu
Total logical cores. For the P/E split on Apple Silicon, read the Total Number of Cores line in system_profiler SPHardwareDataType — it's spelled out (e.g. "11 (5 performance and 6 efficiency)").

RAM

sysctl -n hw.memsize
Total RAM in bytes, not GB. Match the number against the Size reference rather than doing the math.
17179869184 (16 GB)
system_profiler SPMemoryDataType
RAM modules, speed, type (DDR4/LPDDR5/unified), and ECC status. On Apple Silicon, reports memory as on-chip — unified, not user-replaceable.

HD

diskutil info disk0
Scan for Disk Size, Protocol, and SMART Status. Disk Size reports raw formatted capacity, a few percent under the marketed size — round up to the nearest standard capacity (121 GB → 128 GB, 500 GB → 512 GB).
Disk Size: 500.3 GB (500277792768 Bytes) · SMART Status: Verified
diskutil list
All disks and partitions. Confirms the internal SSD is the only fixed disk, and that no leftover external volume is mounted. An empty result here means the SSD was pulled or has failed — record HD = none and flag the unit.
system_profiler SPNVMeDataType
SSD model, firmware, capacity, and TRIM status. Apple Silicon and modern Intel SSDs all show here.

Battery

system_profiler SPPowerDataType
Use this whenever the Mac is booted. Scan for Cycle Count, Condition (Normal / Service Recommended / Service Battery), and Maximum Capacity — reported as a percentage directly, no interpretation. Compare the cycle count to the rated max in the Models tab's battery column.
Cycle Count: 247 · Condition: Normal · Maximum Capacity: 92%
ioreg -rc AppleSmartBattery | egrep "DesignCapacity|MaxCapacity|CycleCount"
Use this in Recovery, where system_profiler SPPowerDataType often won't run on Apple Silicon. The unit MaxCapacity reports differs by era, and Apple Silicon needs AppleRawMaxCapacity instead — see Battery health for the interpretation rules and the health formula.
pmset -g batt
Current charge percentage, charging/discharging state, and time-to-full or time-to-empty. Quick way to confirm the unit actually charges.

Resale blockers — Activation Lock & MDM

Both are booted-only checks; neither works in Recovery. Either one coming back positive stops intake.
system_profiler SPHardwareDataType | grep -i activation
Activation Lock — the most important check. Enabled means the unit is essentially bricked for resale until the previous owner signs out of iCloud and removes the device from Find My. Only T2 Intel (2018+) and Apple Silicon report this line — pre-T2 Intel doesn't support Activation Lock at all, so a missing line is not the same as Disabled. Check the era first.
Activation Lock Status: Disabled
sudo profiles status -type enrollment
MDM / Apple Business Manager enrollment. If Enrolled via DEP: Yes the Mac re-enrolls into a corporate MDM the moment it hits the internet — unsellable until the original org releases it. The profiles binary doesn't exist in recoveryOS; if you can't boot, a Remote Management screen in Setup Assistant is the same signal.
Enrolled via DEP: No · MDM enrollments: None

Firmware Locked

Intel only. Apple Silicon has no firmware password — record N/A. Run these in Recovery, where you're already root.
firmwarepasswd -check
Reports whether a firmware password is set. You only get here if you already cleared the padlock prompt at boot — the password blocks Recovery itself.
firmwarepasswd -delete
Prompts for the current firmware password, then clears it. Authenticates against the firmware, not a macOS account — so it works on a wiped Mac where Startup Security Utility dead-ends with "no admin found". Restart and re-run -check to confirm.

OS Reset

The erase itself happens in Disk Utility — see Step 9. These verify the unit is actually clean afterwards.
fdesetup status
FileVault state. Should read Off on a wiped unit — otherwise the new owner inherits an encrypted disk they can't unlock.
FileVault is Off.
dscl . list /Users
User accounts. Long list — scroll past entries beginning with _ and the system accounts (daemon, nobody, root); what remains should be a single admin account. Multiple human names mean it wasn't erased.
scutil --get ComputerName
Computer name. A properly wiped Mac defaults to the model name (e.g. MacBook Pro). Personal names ("Sarah's MacBook Pro") mean the prior account wasn't removed.
csrutil status
System Integrity Protection. Should be enabled on a properly reset Mac. Disabled means the previous owner was running developer-level tooling — not a deal-breaker, but worth noting.
sw_vers
macOS product name, version, and build number — confirms which OS the unit shipped out on.
ProductVersion: 15.4 · BuildVersion: 24E5238b

Functional Issues

Start with Apple Diagnostics — no OS or password needed. Intel: power on holding D. Apple Silicon: hold power → ⌘D from the Options screen. Record any reference codes, then confirm specific subsystems below.
diskutil info disk0 | grep -i smart
SSD health. Verified is healthy; Failing means refurb-or-parts only. Reported on Intel, T2, and Apple Silicon alike.
SMART Status: Verified
ls /Library/Logs/DiagnosticReports
Recent kernel panics. Look for files ending in .panic — an empty list (or just .ips files) is the goal. Multiple panics suggest failing RAM, a flaky board, or thermal issues.
system_profiler SPCameraDataType
FaceTime camera enumeration. A missing entry is a strong signal of a board-level fault or aftermarket repair. Run SPAudioDataType for built-in mic and speakers.
system_profiler SPAirPortDataType
Wi-Fi module. Look for Card Type, Firmware Version, and Country Code. Confirms the wireless card is recognized — a frequent failure point on older units.
system_profiler SPThunderboltDataType
Thunderbolt / USB-C controllers. Lists each port and what's attached — quick way to verify all ports are alive without dock testing.
system_profiler SPDisplaysDataType
Display and GPU. Built-in resolution, refresh rate, and colour profile, plus any attached external displays. Pair with a visual sweep for dead pixels and backlight bleed.
softwareupdate --list
Latest supported macOS. Confirms the unit can install the current OS — a key data point when grading older Macs that may be EOL.

Quick grading workflow

Five commands, run in order on a booted Mac, fill out a complete intake sheet. For an unknown machine that won't boot — physical inspection, Recovery entry, disk selection, Intel/T2/Apple Silicon nuances — follow the Assessment workflow instead.
system_profiler SPHardwareDataType
1. Name, Identifier, chip, cores, RAM, Serial, and Activation Lock status — all in one readable block.
system_profiler SPPowerDataType
2. Battery cycle count, condition, and maximum capacity.
diskutil info disk0
3. HD size and SMART status.
sudo profiles status -type enrollment
4. The other resale blocker — DEP/MDM enrollment. Cheap to check, expensive to miss.
sudo sysdiagnose -f ~/Desktop
5. Optional but recommended on B-grade or below: drops a full .tar.gz diagnostic bundle on the Desktop. Paper trail for warranty disputes.

Physical Issues

No command produces this column — it's the visual inspection you do before powering on: cosmetic damage, screen condition, keyboard wear, missing screws, liquid damage indicators, engraving or stickers, charger included, SSD present. The checklist and the visual model-identification clues are in Step 1 of the Assessment workflow.

RAM — hw.memsize values

Match the number returned by sysctl hw.memsize to the RAM size.
hw.memsizeApprox GB
Notes on battery health. Apple's rated maximum cycle count is the number of full discharge cycles the battery should sustain while retaining ~80% of original capacity. macOS reports the current cycle count under System Information → Power → Health Information. To check: hold ⌥ while clicking the Apple menu, choose System Information, then Power. Pre-Mid-2009 MacBook Pros and the original MacBook Air used 300-cycle batteries; almost every notebook since Mid-2009 uses a 1000-cycle pack.
